## 🗣️ Сценарий речи преподавателя (Лекционная часть)

### Введение: Ресторанная метафора для REST API
«Коллеги, как общаются между собой современные программы? Представьте себе ресторан:
- Вы (**Клиент**) сидите за столиком и хотите заказать стейк. Вы не идете сами на кухню — это опасно и хаотично.
- Вы зовете официанта. Официант берет ваш заказ, несет его на кухню повару.
- Повар готовит блюдо и отдает официанту. Официант приносит его вам.

Этот **официант** в мире IT называется **API (Application Programming Interface)**. А протокол **HTTP** — это язык, на котором они общаются. 
Сегодня мы разберем два главных механизма связи:
1. **Pull (HTTP Request):** Когда ваш робот сам идет во внешнюю систему и спрашивает: *“Есть ли новые данные?”*.
2. **Push (Webhook):** Когда внешняя система сама «пушит» (стучится) в ваш n8n, как только что-то произошло (например, клиент заполнил форму на сайте)».

### Анатомия HTTP-запроса
«Каждый запрос состоит из:
- **URL (Эндпоинт):** Адрес кухни (куда стучимся).
- **Метод:** 
  - `GET` — попросить данные (посмотреть меню).
  - `POST` — создать новые данные (сделать заказ).
  - `PUT / PATCH` — обновить данные.
  - `DELETE` — удалить данные.
- **Headers (Заголовки):** Служебная информация (авторизация, тип контента `application/json`).
- **Body (Тело запроса):** Сами данные, которые вы передаете».

## 💻 Демонстрация / Практика

### Шаг 1: Настройка Webhook-триггера в n8n
Преподаватель создает ноду `Webhook`:
- Копирует тестовый URL.
- Отправляет тестовый запрос из Postman.
- Демонстрирует, как входящий JSON мгновенно появляется в n8n.

### Шаг 2: Отправка HTTP Request во внешнее API
- Настраиваем ноду `HTTP Request`.
- Подключаем публичное API (например, курс валют или генератор случайных фактов).
- Передаем параметры заголовков (Headers) и авторизации.

## 📝 Домашнее задание и критерии сдачи
1. **Задание:** Создать сценарий в n8n, который принимает входящий Webhook с данными о клиенте (имя, email), делает запрос к внешнему API (например, проверяет валидность email или курс валют) и возвращает обогащенный JSON-ответ.
2. **Критерии сдачи:**
   - Webhook успешно принимает POST-запросы с телом в формате JSON.
   - Нода `HTTP Request` корректно отрабатывает без ошибок авторизации.
   - Итоговый ответ содержит как исходные данные, так и результат от внешнего API.
