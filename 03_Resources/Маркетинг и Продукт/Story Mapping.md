[[_MOC frameworks]]

### 1. Что это такое?

**User Story Mapping (Карта пользовательских историй)** — это инструмент визуализации бэклога продукта, созданный Джеффом Паттерном (Jeff Patton).

В отличие от традиционного плоского бэклога (где фичи просто висят одномерным списком от важных к менее важным), **Story Map — это двухмерная карта**. Она располагает задачи **по шагам пользователя** (слева направо) и **по приоритету реализации** (сверху вниз).

Главная задача Story Mapping — не потерять картинку _целостного пути пользователя_ (User Journey) и научиться нарезать продукт на минимально жизнеспособные релизы (**MVP, Release 1, Release 2**).

### 2. Структура карты: Двухмерная сетка

Карта строится из 4 основных слоев:

Plaintext

```
[ ЭПИКИ / ЦЕЛИ ]       ( 1. Авторизация )         ( 2. Обучение )            ( 3. Обратная связь )
                              │                          │                           │
[ АКТИВНОСТИ ]     [Вход в систему]            [Прохождение урока]        [Сдача ДЗ и вопросы]
                              │                          │                           │
──────────────────────────────┼──────────────────────────┼───────────────────────────┼───────────────────
MVP (Релиз 1)       • Вход по Email/Pass       • Просмотр видео           • Текстовая отправка ДЗ
                    • Сброс пароля             • Кнопка «Сдать ДЗ»        • Чат с ботом в Telegram
──────────────────────────────┼──────────────────────────┼───────────────────────────┼───────────────────
Релиз 2             • Авторизация через Google • Скорость видео (1.5x, 2x)• Загрузка файлов/скриншотов
                    • Авторизация Telegram     • Конспекты под видео      • Голосовые ответы куратора
```

1. **Горизонтальная ось (Слева направо — Время / Путь):**
    
    - **Эпики / Цели (Epics / Goals):** Крупные этапы interaction (например: _Регистрация $\rightarrow$ Покупка $\rightarrow$ Обучение $\rightarrow$ Получение сертификата_).
        
    - **Шаги / Активности (User Activities / Steps):** Конкретные действия, которые совершает пользователь на каждом этапе.
        
2. **Вертикальная ось (Сверху вниз — Приоритет):**
    
    - **Пользовательские истории (User Stories):** Мелкие задачи и фичи, отсортированные от жизненно необходимых (наверху) до опциональных "nice-to-have" (внизу).
        

### 3. Как построить Story Map за 5 шагов

1. **Определи целевого пользователя (Persona):** Кто проходит этот путь? (_например: Студент курса по n8n_).
    
2. **Выпиши скелет (Backbone):** Расположи крупные шаги пользователя слева направо в хронологическом порядке.
    
3. **Наполни картами (Brainstorm Stories):** Под каждым шагом выпиши все фичи и User Stories, которые можно сделать.
    
4. **Проведи линии релизов (Cut Releases):**
    
    - **Проведи горизонтальную черту MVP:** Все карточки выше черты — это минимум, без которого пользователь вообще не сможет пройти путь от начала до конца.
        
    - Ниже черты проведи линии для **Release 2** и **Release 3**.
        
5. **Провалидируй сквозной сценарий (Walkthrough):** Мысленно пройдись слева направо по строчке MVP. Работает ли продукт как единое целое?
    

### 4. Практический пример: Story Map для Telegram-бота автовыдачи курса

Представь, что мы проектируем систему автоматической выдачи уроков и проверки ДЗ через n8n и Telegram.

#### Скелет (Backbone — слева направо):

`Оплата` $\rightarrow$ `Приветствие и регистрация` $\rightarrow$ `Изучение материала` $\rightarrow$ `Проверка ДЗ в n8n`

#### Сетка задач по релизам:

|**Этап пути**|**1. Оплата**|**2. Регистрация**|**3. Изучение**|**4. Проверка ДЗ**|
|---|---|---|---|---|
|**MVP (Релиз 1)**<br><br>  <br><br>_(Собрать за 2 дня)_|• Webhook от Stripe/Tinkoff<br><br>  <br><br>• Запись покупателя в Google Таблицу|• Бот отправляет приветственное сообщение<br><br>  <br><br>• Проверка емейла по базе|• Бот высылает ссылку на закрытое видео на YouTube|• Студент отправляет ссылку на n8n-сценарий<br><br>  <br><br>• n8n пингует куратора в Telegram|
|**Релиз 2**<br><br>  <br><br>_(Улучшение)_|• Авто-генерация промокодов<br><br>  <br><br>• Уведомление об успехе оплаты на почту|• Авторизация по номеру телефона в 1 клик|• Интерактивный список уроков внутри inline-меню бота|• n8n автоматически проверяет доступность n8n Webhook студента (авто-тест)|
|**Релиз 3**<br><br>  <br><br>_(Масштабирование)_|• Реферальная программа ("Приведи друга")|• Личный кабинет студента с прогрессом|• Выдача сертификата в формате PDF после последнего урока|• ИИ-агент (Gemini API) делает первичный ревью кода и даёт совет перед куратором|

### 5. Почему Story Mapping работает лучше обычных бэклогов

- **Видно "дыры" в продукте:** Обычный бэклог может состоять на 80% из задач по оплате и на 20% из выдачи уроков. На Story Map сразу видно, если какой-то шаг пользователя остался без внимания.
    
- **Проще резать MVP:** Вы сразу видите минимальную рабочую полосу (MVP slicing), которая решает проблему целиком, а не отдельный идеально отполированный кусок.
    
- **Удобно переносить в Jira / Obsidian:**
    
    - Строки релиза легко превращаются в **Sprints** или **Releases** в Jira.
        
    - Колоночные эпики становятся **Epics**.
        

### 💡 Как использовать в Obsidian (Папка `1_Atlas` / Проекты):

Создай файл `Story_Map_Название_Проекта.md`. В Obsidian удобно верстать Story Map через Markdown-таблицу (как в примере выше) или связывать задачи в визуальном плагине **Canvas** (Холст), раскладывая стикеры по осям X и Y.
