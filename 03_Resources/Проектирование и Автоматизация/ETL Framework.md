[[_MOC frameworks]]

### 1. Что это такое?

**ETL (Extract, Transform, Load / Извлечение, Трансформация, Загрузка)** — это базовый архитектурный паттерн интеграции и обработки данных. Он описывает трехэтапный процесс переноса информации из источников-источников (сырые данные) в целевую систему (базу данных, хранилище DWH или аналитический сервис).

Существует также современная альтернатива — **ELT**, где данные сначала загружаются «как есть», а потом трансформируются средствами самого хранилища (например, в ClickHouse или BigQuery).

### 2. Три этапа ETL-конвейера (Pipeline)

Plaintext

```
┌───────────────────┐     ┌─────────────────────────┐   ┌───────────────────────┐
│    1. EXTRACT     │     │      2. TRANSFORM       │   │       3. LOAD         │
│    (Извлечение)   │ ──► │   (Трансформация)       │──►│      (Загрузка)       │
│                   │     │                         │   │                       │
│ • REST API        │     │ • Очистка и дедупликация│   │ • PostgreSQL          │
│ • Webhooks        │     │ • Форматирование даты   │   │ • Supabase            │
│ • CSV / Excel     │     │ • ИИ-обогащение (LLM)   │   │ • DWH / ClickHouse    │
│ • SQL DB          │     │ • Валидация типов       │   │ • BI-панели           │
└───────────────────┘     └─────────────────────────┘   └───────────────────────┘
```

#### Разбор этапов:

1. **Extract (Извлечение):**
    
    - Подключение к источникам (REST API, Webhook, базы данных, файлы CSV/JSON, парсинг страниц).
        
    - Забор сырых (raw) данных без изменения их структуры.
        
2. **Transform (Трансформация):**
    
    - **Очистка:** Удаление дубликатов, пустых значений (`null`), фильтрация мусора.
        
    - **Нормализация:** Приведение дат к ISO-формату, нормализация телефонов/email.
        
    - **Обогащение (Enrichment):** Добавление внешних данных или прохождение через LLM (например, Gemini API для определения тональности или суммаризации).
        
    - **Маппинг:** Приведение структуры JSON к схеме целевой БД (**ERD**).
        
3. **Load (Загрузка):**
    
    - Запись обработанных данных в целевую систему с выполнением **CRUD**-операций (`INSERT`, `UPDATE / UPSERT`).
        

### 3. ETL в контексте low-code (n8n) vs Code (Python)

ETL-фреймворки реализуются на разных уровнях сложности:

|**Критерий**|**Low-code ETL (n8n / Make)**|**Code-based ETL (Python / Apache Airflow)**|
|---|---|---|
|**Подходящие задачи**|Интеграции сервисов, ИИ-агенты, парсинг, микро-ETL (до $10^5$- $10^6$ записей/день)|Big Data, тяжелая аналитика, терабайты логов, сложные пайплайны|
|**Инструменты**|n8n, Supabase, Webhooks, Code Node|Python (Pandas, Polars), Airflow, dbt, Prefect|
|**Скорость сборки**|Минуты / часы|Дни / недели|
|**Трансформация**|JS/Python ноды в n8n + Gemini/OpenAI API|Скрипты трансформации Pandas / dbt SQL|

### 4. Практический пример: ETL-процесс в n8n (ИИ-обработка обращений)

Рассмотрим ETL-пайплайн для сбора и обработки отзывов:

Plaintext

```
[Webhook: Форма отзыва]  ──► (Extract: Получить сырой JSON)
                                  │
                                  ▼
[n8n Code Node / Gemini] ──► (Transform: Валидация email + ИИ-оценка sentiment)
                                  │
                                  ▼
[Postgres Node]          ──► (Load: UPSERT в таблицу `feedbacks`)
```

- **Extract:** Webhook принимает JSON формы: `{ "user_email": "test@mail.com", "text": "Все супер, спасибо!" }`.
    
- **Transform:**
    
    1. Код-нода переводит `user_email` в нижний регистр.
        
    2. Gemini API классифицирует `text` $\rightarrow$ `sentiment: "positive"`, `score: 0.95`.
        
- **Load:** Нода PostgreSQL выполняет `INSERT INTO feedbacks ... ON CONFLICT DO UPDATE` (**CRUD**).
    

### 5. Как ETL связывается с остальными нотациями

Вся архитектура обработки данных теперь складывается в единую картину:

1. **DFD (Data Flow Diagram):** Графически проектирует, _откуда_ берется Extract, _где_ происходит Transform и _куда_ идет Load.
    
2. **ERD (Entity-Relationship Diagram):** Задает целевую схему таблиц, под которую подгоняются данные на этапе Transform.
    
3. **DMN (Decision Tables):** Служит «мозгом» на этапе Transform для бизнес-правил (например, расчет скидки или категории).
    
4. **CRUD:** Задает конкретные вызовы методов на этапе Load (`INSERT` / `UPSERT`).
