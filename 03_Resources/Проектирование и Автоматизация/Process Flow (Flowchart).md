[[_MOC frameworks]]

### 1. Что это такое?

**Process Flow Diagram (PFD / Flowchart / Блок-схема процесса)** — это базовый графический инструмент для пошагового описания алгоритма или бизнес-процесса. В отличие от строгих индустриальных нотаций (BPMN или CMMN), блок-схема использует универсальный, интуитивно понятный набор геометрических фигур.

Это «быстрый набросок» процесса: блок-схема идеальна для первого этапа проектирования, инструкции для команды или создания концептуальной схемы работы функции/бота.

### 2. Зачем нужен Process Flow (Flowchart)?

1. **Быстрая визуализация:** Разложить сложную идею или алгоритм на простые шаги за 5–10 минут.
    
2. **Поиск «бутылочных горлышек» (Bottlenecks):** Увидеть дублирующие шаги, лишние согласования и тупиковые развилки.
    
3. **Мостик к автоматизации:** Прежде чем собирать workflow в n8n или писать код, логику проще и дешевле нарисовать в виде блок-схемы.
    

### 3. Стандартные элементы Flowchart (ISO 5807)

Plaintext

```
┌──────────────────┐
│  Start / Stop    │  (Овал / Закругленный прямоугольник — Начало или Конец)
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│     Process      │  (Прямоугольник — Действие / Операция)
└────────┬─────────┘
         │
         ▼
        /  \
       /    \
      /      \    
     /  Dec-  \    (Ромб — Решение / Развилка «Да / Нет»)
     \  ision /
      \  ?   /
       \    /
        \  /
```

|**Фигура**|**Элемент**|**Назначение**|
|---|---|---|
|**Овал / Капсула**|**Terminator**|Начальная или конечная точка процесса (_"Старт"_, _"Успех"_, _"Ошибка"_).|
|**Прямоугольник**|**Process**|Конкретное действие или функция (_"Отправить email"_, _"Распаковать JSON"_).|
|**Ромб**|**Decision**|Условие или развилка (_"Оплачено?"_, _"Email валиден?"_). Имеет минимум 2 выхода (_Да/Нет_).|
|**Параллелограмм**|**Input / Output**|Ввод или вывод данных (_"Ввод промокода"_, _"Печать чека"_).|
|**Параллельные линии**|**Sub-process**|Предопределенный подпроцесс, описанный на отдельной диаграмме.|

### 5. Сравнение Flowchart с другими нотациями процессов

Чтобы не путать инструменты в вашей архитектурной базе знаний:

|**Фреймворк / Нотация**|**Главный фокус**|**Кому подходит**|**Уровень строгости**|
|---|---|---|---|
|**Flowchart (Process Flow)**|Базовая логика и алгоритм действий|Всем (Бизнес, IT, Команда)|🟡 Низкий / Средний|
|**BPMN 2.0**|Строгий исполняемый бизнес-процесс (дорожки, события, таймеры)|Системные аналитики, BPM-движки|🔴 Высокий|
|**DFD (Data Flow)**|Потоки и трансформация **данных** (без развилок по времени)|Архитекторы БД, Backend-разработчики|🔴 Высокий|
|**ETL Pipeline**|Конвейер: **Extract $\rightarrow$ Transform $\rightarrow$ Load**|Data-инженеры, n8n-разработчики|🟡 Средний|

### 💡 Как использовать в вашей базе знаний:

В папке `03_Resources / Архитектура процессов` создай документ `Process_Flow_Diagram.md`.

Используй блок-схемы (например, в формате Mermaid.js прямо внутри Obsidian) на этапе проектирования идеологии любых новых workflows, перед тем как переносить их в n8n или детально документировать в BPMN.
