[[_MOC frameworks]]

### 1. Что это такое?

**CRUD** (Create, Read, Update, Delete) — это базовая концепция программирования и проектирования баз данных, определяющая **4 основные операции** над любой сущностью или ресурсом в системе.

Любая система, работающая с данными (будь то веб-приложение, Telegram-бот, база данных в PostgreSQL или проект в n8n), на фундаментальном уровне выполняет именно эти действия.

### 2. Четыре операции CRUD

|**Операция**|**Действие**|**Расшифровка**|**HTTP-метод (REST API)**|**SQL-запрос**|**Пример (Пользователь)**|
|---|---|---|---|---|---|
|**C** — Create|**Создать**|Добавление новой записи в систему|`POST`|`INSERT`|Регистрация нового студента|
|**R** — Read|**Прочитать**|Получение / чтение списка или одной записи|`GET`|`SELECT`|Просмотр профиля или списка уроков|
|**U** — Update|**Обновить**|Изменение существующей записи (полностью или частично)|`PUT` / `PATCH`|`UPDATE`|Смена пароля, обновление статуса ДЗ|
|**D** — Delete|**Удалить**|Удаление записи из системы|`DELETE`|`DELETE`|Удаление аккаунта, отмена подписки|

### 3. Как CRUD проявляется на разных уровнях архитектуры

Когда ты проектируешь IT-систему или веб-сервис, CRUD проходит сквозь все слои:

Plaintext

```
┌────────────────────────────────────────────────────────────────────────┐
│ UI / Фронтенд:  Кнопка "Создать"  │ Форма ввода  │ Кнопка "Удалить"    │
└───────────────────────────────────┬────────────────────────────────────┘
		                            │ HTTP-запрос (POST / GET / PUT / DELETE)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ API / Бэкенд:   POST /users      │ GET /users   │ DELETE /users/42     │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ SQL / NoSQL Запрос
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ База данных:    INSERT INTO...   │ SELECT FROM..│ DELETE FROM...       │
└────────────────────────────────────────────────────────────────────────┘
```

#### Разбор стандартов:

1. **REST API:**
    
    - `POST /api/v1/courses` — **Create** (Создать курс).
        
    - `GET /api/v1/courses/15` — **Read** (Получить информацию о курсе с ID 15).
        
    - `PATCH /api/v1/courses/15` — **Update** (Обновить отдельные поля курса #15).
        
    - `DELETE /api/v1/courses/15` — **Delete** (Удалить курс #15).
        
2. **Базы данных (SQL):**
    
    - **Create:** `INSERT INTO students (name, email) VALUES ('Никита', 'nikita@example.com');`
        
    - **Read:** `SELECT * FROM students WHERE status = 'active';`
        
    - **Update:** `UPDATE students SET progress = 80 WHERE id = 1;`
        
    - **Delete:** `DELETE FROM students WHERE id = 1;`
        
3. **Автоматизация в n8n:**
    
    - Нода **PostgreSQL / Supabase / Notion** работает по принципу CRUD:
        
        - `Execute Query` (INSERT/SELECT/UPDATE/DELETE)
            
        - Ноды интеграций (например, Telegram, Google Sheets, Airtable) всегда предлагают выбор действия: _Create Row_, _Get Row_, _Update Row_, _Delete Row_.
            

### 4. Hard Delete vs Soft Delete (Важный нюанс проектирования)

При проектировании архитектуры баз данных операцию **Delete** делят на два типа:

- **Hard Delete (Физическое удаление):** Запись навсегда удаляется из базы (`DELETE FROM users...`). Проблема: невозможно восстановить данные, рушатся связи во внешних ключах.
    
- **Soft Delete (Мягкое / Логическое удаление):** Запись остается в базе, но ей проставляется флаг `is_deleted = true` или `deleted_at = "2026-08-31 20:27:00"`.
    
    - _При Read-запросах_ просто добавляется условие `WHERE is_deleted = false`.
        
    - Это стандарт в профессиональной разработке для сохранения истории и аудита.
