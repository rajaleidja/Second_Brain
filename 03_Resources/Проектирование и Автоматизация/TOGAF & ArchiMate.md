[[_MOC frameworks]]

### 1. Что это такое?

**TOGAF (The Open Group Architecture Framework)** и **ArchiMate** — это мировой стандарт «тяжелой артиллерии» в корпоративной архитектуре (Enterprise Architecture / EA).

- **TOGAF** — это **методология и процесс** (инструкция _«Как строить и управлять всей архитектурой организации»_).
    
- **ArchiMate** — это **визуальный язык моделирования** (нотация _«Как нарисовать то, что описано в TOGAF»_).
    

Если **BPMN** описывает один процесс, а **ERD** — одну базу данных, то **TOGAF + ArchiMate** описывают **всю компанию целиком**: от бизнес-стратегии и процессов до серверов, баз данных и конкретных железных стоек в дата-центре.

### 2. Основа TOGAF: Цикл ADM (Architecture Development Method)

Сердце TOGAF — это цикличный метод разработки архитектуры **ADM**. Он делит управление организацией на 8 основных фаз:

Plaintext

```
                  ┌───────────────────────────┐
                  │    Preliminary Phase      │
                  │ (Подготовка и принципы)   │
                  └─────────────┬─────────────┘
                                │
                                ▼
                  ┌───────────────────────────┐
                  │ Phase A: Architecture     │
                  │ Vision (Видение проекта)  │
                  └─────────────┬─────────────┘
                                │
                                ▼
  ┌───────────────────────────────────────────────────────────┐
  │              ПОСТОЯННЫЙ ЦИКЛ ПРОЕКТИРОВАНИЯ               │
  │                                                           │
  │  Phase B: Business Architecture (Процессы, цели, роли)    │
  │                             │                             │
  │                             ▼                             │
  │  Phase C: Information Systems (Приложения и Данные / ERD) │
  │                             │                             │
  │                             ▼                             │
  │  Phase D: Technology Architecture (Инфраструктура/Сервера)│
  └─────────────────────────────┬─────────────────────────────┘
                                │
                                ▼
                  ┌────────────────────────────┐
                  │ Phase E & F: Opportunities │
                  │ & Migration (План перехода)│
                  └────────────────────────────┘
```

### 3. ArchiMate: 3 главных слоя (Layers)

Язык ArchiMate разбивает всю сложность компании на **3 ключевых слоя**, где каждый верхний слой выставляет требования к нижнему:

Plaintext

```
┌─────────────────────────────────────────────────────────────────┐
│ 🟡 БИЗНЕС-СЛОЙ (Business Layer)                                │
│    Бизнес-процессы, Сервисы, Роли, Акторы, Клиенты              │
└─────────────────────────────────┬───────────────────────────────┘
                                  │ Обслуживает (Serves)
                                  ▼
┌─────────────────────────────────────────────────────────────────┐
│ 🔵 СЛОЙ ПРИЛОЖЕНИЙ (Application Layer)                          │
│    Компоненты (n8n, CRM, PostgreSQL), Интерфейсы, REST API      │
└─────────────────────────────────┬───────────────────────────────┘
                                  │ Обслуживает (Serves)
                                  ▼
┌─────────────────────────────────────────────────────────────────┐
│ 🟢 ТЕХНОЛОГИЧЕСКИЙ СЛОЙ (Technology Layer)                      │
│    Сервера (Linux/Docker), Сети, Базы данных, Hardware          │
└─────────────────────────────────────────────────────────────────┘
```

#### Ключевые понятия ArchiMate:

1. **Business Layer (Желтый):** Описывает _что_ делает бизнес. Например, процесс _"Регистрация студента на курс"_.
    
2. **Application Layer (Синий):** Описывает _какие программы_ это обеспечивают. Например, сервис _"n8n Workflow"_ или _"Supabase Auth"_.
    
3. **Technology Layer (Зеленый):** Описывает _на чем_ это крутится. Например, _"Ubuntu Server 24.04"_, _"Docker Container"_, _"Postgres Node"_.
    

### 4. Практический пример: Модель ArchiMate для автоматизации в n8n

Представь сквозное описание сервиса обработки заявок:

- **Бизнес-слой (Желтый):**
    
    - Процесс: `Прием и обработка отзывов` $\rightarrow$ Обслуживается приложением.
        
- **Слой приложений (Синий):**
    
    - Компонент: `n8n Webhook Node` (принимает данные).
        
    - Компонент: `Gemini API Service` (анализирует текст).
        
    - Данные: `Feedback Record` (объект данных).
        
- **Технологический слой (Зеленый):**
    
    - Узел (Node): `Hetzner Cloud VPS` (ОС Linux Mint / Ubuntu).
        
    - Сервис: `Docker Daemon` $\rightarrow$ запускает контейнер `n8n_instance`.
        

### 5. Итоговая карта всех фреймворков и нотаций (Полный стек)

Plaintext

```
[ БИЗНЕС-СТРАТЕГИЯ И АУДИТ ]
  ├── Lean Canvas / VPC / JTBD   ──► Формулирование ценности и бизнес-модели
  └── SIPOC / 5 Why              ──► Верхнеуровневый аудит и поиск проблем

[ КОРПОРАТИВНАЯ АРХИТЕКТУРА (МАКРО-УРОВЕНЬ) ]
  └── TOGAF & ArchiMate          ──► Связь Бизнеса 🟡 + Софта 🔵 + Железа 🟢

[ ПРОЕКТИРОВАНИЕ ПРОЦЕССОВ И ЛОГИКИ ]
  ├── BPMN 2.0 / CMMN / DMN      ──► Исполняемые процессы, кейсы и правила
  └── Process Flow (Flowchart)   ──► Быстрые алгоритмы и блок-схемы

[ МОДЕЛИРОВАНИЕ ДАННЫХ И ИНТЕГРАЦИЙ ]
  ├── DFD (Data Flow Diagram)    ──► Потоки данных между модулями
  ├── ERD (Entity-Relationship)  ──► Схема таблиц и связей в БД (SQL/Supabase)
  ├── ETL Framework              ──► Конвейеры обработки: Extract ➔ Transform ➔ Load
  └── CRUD                       ──► Стандарты манипуляции данными (Create/Read/Update/Delete)

[ УПРАВЛЕНИЕ РАЗРАБОТКОЙ ]
  └── Jira (Epics/Tasks/MOC)     ──► Нарезка задач и ведение бэклога
```

### 💡 Как использовать в вашей базе знаний:

В папке `03_Resources / Архитектура процессов` создай документ `TOGAF_and_ArchiMate.md`.

Используй концепцию слоев ArchiMate (Бизнес $\rightarrow$ Приложения $\rightarrow$ Инфраструктура), когда нужно составить архитектурную карту сложного проекта с серверами, базами данных и автоматизациями.
