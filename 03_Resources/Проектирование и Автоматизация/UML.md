[[_MOC frameworks]]

### 1. Что это такое?

**UML (Unified Modeling Language / Унифицированный язык моделирования)** — это общепринятый стандартный язык графического описания, визуализации и проектирования программных систем.

Если **BPMN** создан для описания _бизнес-процессов_, а **ArchiMate** — для _всякой корпоративной архитектуры (бизнес + IT + железо)_, то **UML** нацелен на **детализацию внутри самого программного обеспечения** (архитектура кода, классы, взаимодействие компонентов, сценарии использования).

### 2. Зачем нужен UML?

1. **Мостик от требований к коду:** Переводит бизнес-требования на язык, понятный разработчикам (ООП, базы данных, архитектура модулей).
    
2. **Стандартизация ООП:** Позволяет спроектировать классы, интерфейсы и их наследование до написания первой строчки кода.
    
3. **Визуализация взаимодействия:** Покажет step-by-step, как микросервисы или объекты обмениваются сообщениями по времени.
    

### 3. Структура диаграмм UML (20+ видов в двух группах)

Все диаграммы UML делятся на две основные категории: **Структурные** (статические) и **Поведенческие** (динамические).

Plaintext

```
                               ┌───────────────────────────┐
                               │       UML-ДИАГРАММЫ       │
                               └─────────────┬─────────────┘
                                             │
                      ┌──────────────────────┴──────────────────────┐
                      ▼                                             ▼
        ┌───────────────────────────┐                 ┌───────────────────────────┐
        │ СТРУКТУРНЫЕ (Structural)  │                 │ ПОВЕДЕНЧЕСКИЕ (Behavioral)│
        │  (Что из чего состоит)    │                 │   (Как работает во времени)│
        ├───────────────────────────┤                 ├───────────────────────────┤
        │ • Class Diagram           │                 │ • Sequence Diagram        │
        │ • Component Diagram       │                 │ • Use Case Diagram        │
        │ • Deployment Diagram      │                 │ • State Machine Diagram   │
        └───────────────────────────┘                 └───────────────────────────┘
```

### 4. ТОП-4 самых важных диаграмм UML для разработчиков и аналитиков

#### 1. Use Case Diagram (Диаграмма прецедентов использования)

Показывает **актеров** (пользователей, внешние системы) и **сценарии** (что они могут делать в системе).

- _Элементы:_ Актер (человечек), Use Case (овал), связи.
    
- _Зачем:_ Сбор требований и составление бэклога задач (User Stories).
    

#### 2. Sequence Diagram (Диаграмма последовательности)

Показывает **взаимодействие объектов/микросервисов во времени**.

- _Элементы:_ Линии жизни (Lifelines), стрелки запросов (`http POST`, `SQL select`) и ответов.
    
- _Зачем:_ Проектирование REST API, взаимодействия нод в n8n, микросервисов, интеграций с LLM/Postgres.
    

Plaintext

```
Client / Frontend              n8n Webhook               Gemini API               PostgreSQL
      │                             │                         │                        │
      │ ─── 1. POST /feedback ────► │                         │                        │
      │                             │ ─── 2. Analyze text ──► │                        │
      │                             │ ◄── 3. Sentiment JSON ──│                        │
      │                             │                                                  │
      │                             │ ─── 4. INSERT INTO feedbacks ──────────────────► │
      │                             │ ◄── 5. OK (201 Created) ─────────────────────────│
      │ ◄── 6. 200 Success ──────── │                         │                        │
```

#### 3. Class Diagram (Диаграмма классов)

Описывает структуру объектно-ориентированного кода: классы, их атрибуты, методы и связи между ними (наследование, агрегация, композиция).

- _Зачем:_ Архитектура Backend-приложений и проектирование ORM-моделей.
    

#### 4. State Machine Diagram (Диаграмма состояний)

Показывает жизненный цикл объекта и переходы между его состояниями (например, _Заказ: Черновик $\rightarrow$ Оплачен $\rightarrow$ В доставке $\rightarrow$ Завершен_).

- _Зачем:_ Проектирование сложных сущностей с бизнес-правилами (похоже на **CMMN**).
    

### 5. Полноценная картина: Как UML дополняет твою систему знаний

Теперь твоя матрица визуального и системного анализа стала абсолютно полной:

|**Сфера применения**|**Лучшие фреймворки / Нотации**|
|---|---|
|**Бизнес-модель и Потребности**|Lean Canvas, Value Proposition Canvas (VPC), JTBD|
|**Аудит процессов**|SIPOC, 5 Why|
|**Корпоративная Архитектура**|TOGAF & ArchiMate (Бизнес + Софт + Железо)|
|**Бизнес-процессы и Логика**|BPMN 2.0 (процессы), CMMN (кейсы), DMN (правила), Flowchart (алгоритмы)|
|**Программирование и Софт**|**UML** (Use Cases, Sequence, Class Diagrams)|
|**Данные и Архитектура БД**|DFD (потоки данных), ERD (схема БД), ETL (обработка), CRUD (API-методы)|
|**Управление проектом**|Jira (Epics / Tasks / Sub-tasks), Obsidian (MOC / ACCESS / PARA)|

### 💡 Как использовать в вашей базе знаний:

В папке `03_Resources / Архитектура процессов` (или `IT и Разработка`) создай документ `UML_Diagrams.md`.

_Для быстрой отрисовки Sequence и Use Case диаграмм прямо в Obsidian лучше всего использовать синтаксис **Mermaid.js** (код рендерится в схемы прямо в заметке)._
