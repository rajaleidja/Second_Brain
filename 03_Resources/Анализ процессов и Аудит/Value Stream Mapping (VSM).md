[[_MOC frameworks]]

### 1. Что это такое?

**Value Stream Mapping (VSM / Карта потока создания ценности)** — это visual-инструмент бережливого производства (Lean), представляющий собой подробную схему всех материальных, информационных и логических шагов, необходимых для доставки продукта или услуги от начального запроса клиента до конечного результата.

В отличие от стандартного **Process Flow** или **BPMN**, VSM фокусируется не просто на последовательности действий, а на **разделении времени на ценное и неценное**, а также на **потоке информации и запасов (WIP)**.

> 💡 **Главная цель VSM:** Визуализировать и сократить **Lead Time** (полный цикл выполнения) за счет обнаружения скрытых потерь (Muda), пролеживания задач в очередях и задержек при передаче между этапами/командами.

### 2. Ключевые метрики VSM: PT, WT, LT и PCE

Каждый элемент карты VSM сопровождается «блоком данных» (Data Box) с ключевыми метриками:

Plaintext

```
┌────────────────────────────────────────────────────────────────────────┐
│                   КЛЮЧЕВЫЕ МЕТРИКИ ПОТОКА (DATA BOX)                   │
├────────────────────────────────────────────────────────────────────────┤
│ • Process Time (PT / Touch Time): Время непосредственной полезной      │
│   работы над задачей (например, написание кода, составление отчета).   │
│                                                                        │
│ • Wait Time (WT / Queue Time): Время простоя задачи в очереди,         │
│   ожидания ревью, утверждения или освобождения исполнителя.            │
│                                                                        │
│ • Lead Time (LT): Полное время от входа задачи до выхода (LT = PT + WT)│
│                                                                        │
│ • PCE (Process Cycle Efficiency): Эффективность цикла процесса:        │
│                                                                        │
│                          Process Time (PT)                             │
│                 PCE = ───────────────────────── × 100%                 │
│                            Lead Time (LT)                              │
└────────────────────────────────────────────────────────────────────────┘
```

> ⚠️ В неоптимизированных IT- и бизнес-процессах показатель **PCE часто составляет всего 5–15%**. Это означает, что 85–95% времени задача просто «лежит в очереди» (Wait Time).

### 3. Структура карты VSM (Временная пила)

Внизу карты VSM обязательно рисуется **«временная пила» (Time Line)**, которая разделяет полезное время (внизу) и время ожидания (вверху):

Plaintext

```
[ Управленческий / Информационный поток (Jira, Webhooks, E-mail) ]
  │                                                                 │
  ▼                                                                 ▼
┌────────────┐     Очередь      ┌──────────────┐      Очередь     ┌─────────────┐
│ Разработка ├─────────────────►│ Тестирование ├─────────────────►│ Деплойment  │
│(PT =4 часа)│    (WT = 24 ч)   │ (PT = 2 часа)│    (WT = 18 ч)   │(PT = 1 час) │
└────────────┘                  └──────────────┘                  └─────────────┘
  │                               │                                │
──┘                               └──                              └───(TimeLine)
    Wait: 24h                         Wait: 18h                        
  ─────────────────────────────────────────────────────────────────────────►
   Work: 4h                           Work: 2h                         Work: 1h

───────────────────────────────────────────────────────────────────────────
 SUMMARY:
 • Total Process Time (PT) = 4h + 2h + 1h = 7 hours
 • Total Lead Time (LT)    = 7h + 24h + 18h = 49 hours
 • PCE (Эффективность)    = (7 / 49) * 100% = 14.2%
```

### 4. Текущее состояние (Current State) vs Будущее состояние (Future State)

Работа с VSM всегда состоит из двух шагов:

1. **Current State Map (Карта текущего состояния):** Фиксирует реальное положение дел «как есть» (As-Is). Составляется на основе **Gemba Walk** и реальных логов/метрик Jira, а не со слов менеджеров.
    
2. **Future State Map (Карта будущего состояния):** Проектирует целевое состояние (To-Be) после устранения узких мест по **TOC**, внедрения **WIP-лимитов Kanban** и автоматизации рутинных шагов (n8n / CI/CD).
    

### 5. Связка VSM с другими методологиями

|**Методология / Фреймворк**|**Роль и связь с VSM**|
|---|---|
|**Six Sigma (DMAIC)**|VSM — главный инструмент на этапах **Measure (M)** и **Analyze (A)** для точного расчета задержек и потерь.|
|**Теория ограничений (TOC)**|VSM наглядно подсвечивает, перед каким именно этапом скапливается наибольшее время ожидания (WT), указывая на бутылочное горлышко.|
|**Gemba Walk**|Карта VSM не чертится из кабинета — данные для PT и WT собираются через личное наблюдение за процессом (Gemba).|
|**Kanban**|Внедрение WIP-лимитов и сигналов Pull в Kanban сокращает время простоя (WT) на карте VSM.|
|**SIPOC**|SIPOC задает контекст верхнего уровня (входы/выходы), а VSM углубляется в метрики времени и очереди внутри этого процесса.|

### 6. Полная систематизированная матрица фреймворков

Твой систематизированный арсенал управления качеством, анализом процессов и продуктовой архитектурой:

Plaintext

```
[ УПРАВЛЕНИЕ КАЧЕСТВОМ И ОПТИМИЗАЦИЯ (LEAN SIX SIGMA & TOC) ]
  ├── Value Stream Mapping (VSM) ──► Картографирование потока ценности и расчет эффективности (PT, WT, LT, PCE)
  ├── Six Sigma (DMAIC)          ──► 5 этапов снижения дефектов (Define-Measure-Analyze-Improve-Control)
  ├── Kaizen & 5S                ──► Непрерывное развитие и 5 шагов организации порядка (Digital 5S)
  ├── Gemba Walk                 ──► Наблюдение за процессами на месте их выполнения (3G / 3M)
  ├── Теория ограничений (TOC)   ──► Поиск и расширение узких мест (5 Focusing Steps / DBR)
  ├── SIPOC                      ──► Верхнеуровневый аудит процессов (P ➔ O ➔ C ➔ I ➔ S)
  ├── Диаграмма Исикавы (Fishbone)──► Системный поиск причин сбоев по 6M / 5P
  └── 5 Why                      ──► Глубокий поиск корневых причин (Root Cause Analysis)

[ СТРАТЕГИЯ, ЦЕЛИ И КОМАНДА ]
  ├── Lean Canvas / VPC / JTBD   ──► Оценка продукта, ценности и пользователей
  ├── OKRs & SMART               ──► Постановка целей (OKR) и точных задач (SMART)
  ├── RACI / RASCI Matrix        ──► Распределение ролей и ответственности (A, R, C, I)
  ├── Матрица Эйзенхауэра        ──► Важно / Срочно (Личный фокус на Q2)
  └── MoSCoW / RICE / Kano       ──► Приоритезация бэклога задач и фич

[ ИСПОЛНЕНИЕ И МЕТОДОЛОГИЯ ]
  ├── Scrum                      ──► Итерации (спринты), роли, события
  └── Kanban / Scrumban          ──► Непрерывный поток, WIP-лимиты, Lead/Cycle Time

[ КОРПОРАТИВНАЯ И СОФТВЕРНАЯ АРХИТЕКТУРА ]
  ├── TOGAF & ArchiMate          ──► Бизнес 🟡 + Софт 🔵 + Инфраструктура 🟢
  ├── BPMN / CMMN / DMN          ──► Процессы, кейсы, правила решений
  ├── Process Flow (Flowchart)   ──► Пошаговые алгоритмы
  └── UML                        ──► Диаграммы Sequence, Class, Use Case

[ ДАННЫЕ И ИНТЕГРАЦИИ ]
  ├── DFD                        ──► Потоки данных
  ├── ERD                        ──► Схемы баз данных (PostgreSQL / Supabase)
  ├── ETL Framework              ──► Конвейеры обработки данных
  └── CRUD                       ──► Операции базы данных и REST API

[ ОРГАНИЗАЦИЯ И ТРЕКИНГ ]
  ├── Jira                       ──► Иерархия (Epics / Tasks / Sub-tasks)
  └── Obsidian                   ──► MOC / ACCESS / PARA
```

### 💡 Как использовать в вашей базе знаний:

В папке `03_Resources / Анализ процессов` создай документ `Value_Stream_Mapping_VSM.md`.

Используй VSM для построения карт процессов разработки или автоматизации, чтобы точно знать, где задачи теряют время в ожидании.
