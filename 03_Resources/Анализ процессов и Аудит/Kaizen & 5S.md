[[_MOC frameworks]]

### 1. Что это такое?

**Kaizen (Кайдзен)** и **5S** — это фундаментальные философии и практики бережливого производства (Lean), родившиеся в Японии (преимущественно в рамках Toyota Production System).

- **Kaizen (改善):** В переводе означает _«изменение к лучшему»_ («kai» — изменение, «zen» — хорошо). Это философия **непрерывного, ежедневного и точечного улучшения** всех процессов всеми сотрудниками компании — от рядового инженера до CEO.
    
- **5S:** Это базовый инструмент Kaizen для **организации рабочего пространства** (как физического, так и цифрового). Наведение и поддержание абсолютного порядка — это первый шаг к устранению потерь (Muda).
    

### 2. Философия Kaizen: Маленькие шаги vs Большие революции

В отличие от западного подхода «Инновации / Реинжиниринг» (где процессы ломают и строят с нуля раз в несколько лет), Kaizen ориентирован на постоянные микро-улучшения.

Plaintext

```
ИННОВАЦИИ (Западный подход)            KA I ZEN (Японский подход)
     ▲                                       ▲
     │       ┌───                      │         /
     │   ┌───┘                         │        /  (Постоянный,
     │───┘ (Скачкообразно)             │       /    непрерывный рост)
     └────────────────────────►        └────────────────────────►
```

#### Ключевые принципы Kaizen:

1. **Отказ от идеала в пользу действия:** «Сделай на 1% лучше сегодня, чем вчера».
    
2. **Устранение 8 видов потерь (Muda):** Перепроизводство, ожидание, лишняя транспортировка, избыточная обработка, запасы, лишние движения, дефекты/баги, нереализованный потенциал сотрудников.
    
3. **Иди на Гембу (Gemba):** Проблемы решаются там, где они возникают, на основе реальных данных.
    
4. **Визуализация проблем:** Проблема — это не катастрофа, а возможность для улучшения.
    

### 3. Система 5S: Организация порядка в 5 шагов

Система 5S состоит из пяти последовательных шагов, каждый из которых начинается на букву **S**:

Plaintext

```
┌─────────────────┬───────────────────┬────────────────────────────────────────────────────────┐
│ Шаг (Японский)  │ Шаг (Русский)     │ Суть действия (Физический & Цифровой мир)               │
├─────────────────┼───────────────────┼────────────────────────────────────────────────────────┤
│ 1. Seiri (整理)  │ **Сортировка**    │ Четкое разделение вещей/файлов на нужные и ненужные.    │
│                 │                   │ Удалить/заархивировать всё, что не используется.       │
├─────────────────┼───────────────────┼────────────────────────────────────────────────────────┤
│ 2. Seiton (整頓) │ **Соблюдение      │ «Место для всего, и всё на своем месте».               │
│                 │  порядка**        │ Упорядочить структуру папок, иерархию Obsidian/Jira.   │
├─────────────────┼───────────────────┼────────────────────────────────────────────────────────┤
│ 3. Seiso (清掃)  │ **Содержание      │ Содержи рабочее место, код и документацию в чистоте.   │
│                 │  в чистоте**      │ Регулярная очистка логов, рефакторинг, удаление legacy.│
├─────────────────┼───────────────────┼────────────────────────────────────────────────────────┤
│ 4. Seiketsu     │ **Стандартизация**│ Закрепление первых 3S в виде регламентов, шаблонов     │
│    (清潔)       │                   │ и чек-листов (например, структуры PARA/ACCESS).        │
├─────────────────┼───────────────────┼────────────────────────────────────────────────────────┤
│ 5. Shitsuke     │ **Совершенство-   │ Превращение соблюдения правил в привычку и культуру.   │
│    (躾)         │  вание**          │ Самодисциплина и регулярный аудит порядка.             │
└─────────────────┴───────────────────┴────────────────────────────────────────────────────────┘
```

### 4. Применение 5S в Цифровой Среде и Инженерии (Digital 5S)

Система 5S идеально ложится на организацию файлов, Obsidian, Jira и рабочий стол Linux/Windows:

Plaintext

```
[ DIGITAL 5S В ВАШЕЙ СИСТЕМЕ ]

1. SEIRI (Сортировка)
   ├── Удалить временные лог-файлы, старые дубликаты CSV
   └── В Obsidian: архивировать завершенные проекты из 01_Projects в 04_Archive

2. SEITON (Порядок)
   ├── Применить структуру PARA / ACCESS для файлов и заметок
   └── В Jira: чёткая структура Epics ➔ Tasks ➔ Sub-tasks (без «потерянных» задач)

3. SEISO (Чистота)
   ├── Регулярный рефакторинг кода и конфигураций (n8n, Docker compose)
   └── Очистка папки «Downloads» и рабочего стола раз в неделю

4. SEIKETSU (Стандартизация)
   ├── Единые шаблоны для Post-Mortem, 5 Why, SIPOC и архитектурных заметок
   └── Naming Conventions для Git-коммитов и файлов

5. SHITSUKE (Дисциплина)
   └── Проведение еженедельного Weekly Review для поддержания системы в актуальном состоянии
```

### 5. Как Kaizen и 5S связываются с остальными фреймворками

|**Фреймворк**|**В чем роль**|**Связь с Kaizen & 5S**|
|---|---|---|
|**Gemba Walk**|Наблюдение за процессами|Gemba Walk позволяет увидеть, где нарушаются стандарты 5S и где есть потери (Muda).|
|**Retrospective (Scrum)**|Поиск точек роста|Каждая Ретроспектива — это прямое воплощение Kaizen (выработка 1–2 микро-улучшений на следующий спринт).|
|**Теория ограничений (TOC)**|Фокус на узком месте|Kaizen-улучшения в первую очередь направляются на расширение ограничения системы.|
|**Obsidian (PARA / ACCESS)**|База знаний|5S является методологическим фундаментом для поддержания чистоты в Obsidian.|

### 6. Полный систематизированный стек инструментов

Твоя база знаний по бережливому производству, анализу процессов и управлению:

Plaintext

```
[ АУДИТ ПРОЦЕССОВ И ПОИСК ПОТЕРЬ (LEAN & KAIZEN) ]
  ├── Kaizen & 5S                ──► Непрерывное развитие и 5 шагов организации порядка (Digital 5S)
  ├── Gemba Walk                 ──► Наблюдение за процессами на месте их выполнения (3G / 3M)
  ├── Теория ограничений (TOC)   ──► Поиск и расширение узких мест (5 Focusing Steps / DBR)
  ├── SIPOC                      ──► Верхнеуровневый аудит процессов (P ➔ O ➔ C ➔ I ➔ S)
  ├── Диаграмма Исикавы (Fishbone)──► Системный поиск причин сбоев по 6M / 5P
  └── 5 Why                      ──► Глубокий поиск корневых причин (Root Cause Analysis)

[ СТРАТЕГИЯ, ЦЕЛИ И КОМАНДА ]
  ├── Lean Canvas / VPC / JTBD   ──► Оценка продукта, ценности и пользователей
  ├── OKRs & SMART               ──► Постановка целей (OKR) и точных задач (SMART)
  ├── RACI / RASCI Matrix        ──► Распределение ролей и ответственности (A, R, C, I)
  ├── Матрица Эйзенхауэра        ──► Важно / Срочно (Личный фокус на Q2)
  └── MoSCoW / RICE / Kano       ──► Приоритезация бэклога задач и фич

[ ИСПОЛНЕНИЕ И МЕТОДОЛОГИЯ ]
  ├── Scrum                      ──► Итерации (спринты), роли, события
  └── Kanban / Scrumban          ──► Непрерывный поток, WIP-лимиты, Lead/Cycle Time

[ КОРПОРАТИВНАЯ И СОФТВЕРНАЯ АРХИТЕКТУРА ]
  ├── TOGAF & ArchiMate          ──► Бизнес 🟡 + Софт 🔵 + Инфраструктура 🟢
  ├── BPMN / CMMN / DMN          ──► Процессы, кейсы, правила решений
  ├── Process Flow (Flowchart)   ──► Пошаговые алгоритмы
  └── UML                        ──► Диаграммы Sequence, Class, Use Case

[ ДАННЫЕ И ИНТЕГРАЦИИ ]
  ├── DFD                        ──► Потоки данных
  ├── ERD                        ──► Схемы баз данных (PostgreSQL / Supabase)
  ├── ETL Framework              ──► Конвейеры обработки данных
  └── CRUD                       ──► Операции базы данных и REST API

[ ОРГАНИЗАЦИЯ И ТРЕКИНГ ]
  ├── Jira                       ──► Иерархия (Epics / Tasks / Sub-tasks)
  └── Obsidian                   ──► MOC / ACCESS / PARA
```
