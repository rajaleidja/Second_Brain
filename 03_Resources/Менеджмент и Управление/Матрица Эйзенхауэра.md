[[_MOC frameworks]]

### 1. Что это такое?

**Матрица Эйзенхауэра (Eisenhower Matrix / Приоритетная матрица)** — это классический фреймворк тайм-менеджмента и принятия решений. Он помогает распределить задачи по двум ключевым критериям: **Важность (Importance)** и **Срочность (Urgency)**.

Авторство идеи принадлежит 34-му президенту США Дуайту Эйзенхауэру, который сформулировал знаменитый принцип:

> _"У меня есть две проблемы: срочная и важная. Срочная не бывает важной, а важная — срочной."_

### 2. Структура 4-х квадрантов

Все поступающие задачи раскладываются на сетку $2 \times 2$:

Plaintext

```
                  ВАЖНО                       НЕ ВАЖНО
         ┌───────────────────────────┬───────────────────────────┐
         │  Квадрант 1: СДЕЛАЙ       │  Квадрант 3: ДЕЛЕГИРУЙ    │
         │  (Do First)               │  (Delegate)               │
  СРОЧНО │                           │                           │
         │ • Горящие дедлайны        │ • Рутинные входящие       │
         │ • Аварии и сбои (Incident)│ • Мелкие чужие просьбы    │
         │ • Критические баги        │ • Уведомления и спам      │
         ├───────────────────────────┼───────────────────────────┤
         │  Квадрант 2: ЗАПЛАНИРУЙ   │  Квадрант 4: УДАЛИ        │
         │  (Schedule / Focus Zone)  │  (Eliminate)              │
НЕ СРОЧНО│                           │                           │
         │ • Обучение и развитие     │ • Пожиратели времени      │
         │ • Проектирование(ERD/BPMN)│ • Бессмысленный скроллинг │
         │ • Автоматизация процессов │ • Лишние встречи          │
         └───────────────────────────┴───────────────────────────┘
```

#### Разбор квадрантов:

1. **Q1: Важно и Срочно (Кризисы / Firefighting)**
    
    - **Действие:** Сделать немедленно самому.
        
    - **Пример:** Упал сервер PostgreSQL, сорвался дедлайн по проекту, критическая ошибка в прод-продукте.
        
    - _Цель:_ Минимизировать время, проводимое в этом квадранте, за счет хорошего проектирования.
        
2. **Q2: Важно, но Не срочно (Зона стратегического роста)**
    
    - **Действие:** Запланировать точное время в календаре / Jira.
        
    - **Пример:** Проектирование базы данных (ERD), написание документации, изучение ETL/UML, спорт, планирование бэклога в Jira.
        
    - _Цель:_ Проводить здесь **80% рабочего времени**. Именно эти задачи дают наибольший стратегический эффект.
        
3. **Q3: Срочно, но Не важно (Ловушка суеты)**
    
    - **Действие:** Делегировать, автоматизировать (n8n / ИИ-агенты) или упростить.
        
    - **Пример:** Сборка простых отчетов вручную, первичный разбор входящей почты, рутинные уведомления.
        
4. **Q4: Не важно и Не срочно (Шум и мусор)**
    
    - **Действие:** Беспощадно вычеркнуть и безжалостно отбросить.
        
    - **Пример:** Бесконечный скроллинг соцсетей, оптимизация того, что и так работает и не приносит пользы.
        

### 3. Как связать Матрицу Эйзенхауэра с Jira и Obsidian

Чтобы матрица не осталась лишь "красивой теорией", интегрируй её в свои инструменты:

#### В Jira:

- **Q1 (Важно/Срочно):** Ишью с приоритетом `Highest / Blocker` и текущим спринтом.
    
- **Q2 (Важно/Не срочно):** Эпики (`Epics`), задачи планирования архитектуры, задачи по обучению и развитию с приоритетом `High / Medium` в бэклоге.
    
- **Q3 (Срочно/Не важно):** Кандидаты на автоматизацию с помощью скриптов или n8n workflows (`Priority: Low`).
    
- **Q4 (Не важно/Не срочно):** Отклоненные задачи (`Status: Won't Do / Closed`).
    

#### В Obsidian:

При использовании структуры **PARA** / **ACCESS**:

- В ежедневной заметке (Daily Note) тегируй задачи или дели чек-лист по 4 блокам: `#q1_do`, `#q2_schedule`, `#q3_delegate`, `#q4_eliminate`.
    

### 4. Итоговая матрица всех инструментов системного инженера

Теперь в твоей базе знаний есть исчерпывающий набор инструментов под любую задачу:

Plaintext

```
[ УПРАВЛЕНИЕ ВРЕМЕНЕМ И ПРИОРИТЕТАМИ ]
  └── Матрица Эйзенхауэра        ──► Срочно / Важно (Фокус на Q2)

[ БИЗНЕС-СТРАТЕГИЯ И АУДИТ ]
  ├── Lean Canvas / VPC / JTBD   ──► Продукт, ценность и потребители
  └── SIPOC / 5 Why              ──► Аудит процессов и поиск корневых причин

[ АРХИТЕКТУРА И МОДЕЛИРОВАНИЕ ]
  ├── TOGAF & ArchiMate          ──► Макро-уровень: Бизнес 🟡 + Софт 🔵 + Железо 🟢
  ├── BPMN / CMMN / DMN          ──► Процессы, кейсы, правила решений
  ├── Process Flow (Flowchart)   ──► Быстрые алгоритмы
  └── UML                        ──► Сценарии, последовательности (Sequence) и классы софта

[ ДАННЫЕ И ИНТЕГРАЦИИ ]
  ├── DFD                        ──► Потоки данных
  ├── ERD                        ──► Проектирование БД (SQL/Supabase)
  ├── ETL                        ──► Конвейеры (Extract ➔ Transform ➔ Load)
  └── CRUD                       ──► Операции и методы API

[ ОРГАНИЗАЦИЯ И ТРЕКИНГ ]
  ├── Jira                       ──► Epics / Tasks / Sub-tasks
  └── Obsidian                   ──► MOC / ACCESS / PARA
```

### 💡 Как использовать в вашей базе знаний:

В папке `03_Resources / Личная продуктивность` (или `Управление проектами`) создай документ `Eisenhower_Matrix.md`.

Используй принцип Q2 ("Важно, но Не срочно"), чтобы выделять системные блоки времени на архитектуру, учебу и сборку автоматизаций.
