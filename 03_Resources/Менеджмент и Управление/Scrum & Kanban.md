[[_MOC frameworks]]

### 1. Что это такое?

**Scrum и Kanban** — это два главных методологических фреймворка из семейства **Agile (гибкой разработки)**.

Если **OKRs** задают стратегический вектор, а **RICE / MoSCoW** расставляют приоритеты, то Scrum и Kanban определяют **механику ежедневного движения задач** от идеи до работающего результата в Jira.

### 2. Scrum: Итеративная разработка и фиксированный ритм

Scrum строится на **спринтах** (коротких фиксированных итерациях продолжительностью от 1 до 4 недель). Главная цель каждого спринта — поставить работающий приращение продукта (**Increment**).

Plaintext

```
                                СИНХРОНИЗАЦИЯ
                             ┌─────────────────┐
                             │  Daily Scrum    │ (15 мин каждый день)
                             └────────┬────────┘
                                      │
┌──────────────┐   Планирование  ┌────▼────────┐      Разработка     ┌──────────────┐
│ Product      ├────────────────►│ Sprint      ├────────────────────►│ Potentially  │
│ Backlog      │   (Sprint Plan) │ Backlog     │     (1-2 недели)    │ Shippable    │
└──────────────┘                 └─────────────┘                     │ Increment    │
                                                                     └──────┬───────┘
                                                                            │
                                 ┌──────────────┐                           │
                                 │ Retrospective│◄──────────────────────────┘
                                 └──────────────┘    Обзор (Demo) & Ретро
```

#### Ключевые роли (Scrum Roles):

- **Product Owner (ПО):** Управляет бэклогом продукта, расставляет приоритеты (по RICE/MoSCoW), формулирует SMART-цели спринта.
    
- **Scrum Master (SM):** Фасилитатор процесса. Убирает блокеры, следит за соблюдением правил Agile и помогает команде.
    
- **Developers (Команда разработки):** Кросс-функциональная группа, которая берет задачи из бэклога и претворяет их в код/конфигурации.
    

#### Ключевые артефакты и события:

1. **Sprint Planning:** Отбор задач из Product Backlog в Sprint Backlog под объём ресурсов (Capacity).
    
2. **Daily Scrum (Daily Standup):** 15-минутная синхронизация: _Что сделал? Что буду делать? Какие есть блокеры?_
    
3. **Sprint Review (Demo):** Демонстрация готового функционала заказчикам/пользователям.
    
4. **Retrospective (Ретро):** Анализ процесса: _Что прошло хорошо? Что улучшить в следующем спринте?_
    

### 3. Kanban: Непрерывный поток и лимиты незавершенной работы (WIP)

Kanban основан на принципах **бережливого производства (Lean)** и визуализации всего потока создания ценности. Здесь нет жестких спринтов — задачи двигаются непрерывно по мере освобождения ресурсов.

Plaintext

```
┌─────────────────┬─────────────────┬─────────────────┬─────────────────┐
│     BACKLOG     │   IN PROGRESS   │     TESTING     │      DONE       │
│                 │  [ WIP Limit: 2]│  [ WIP Limit: 2]│                 │
│                 │                 │                 │                 │
│  [Task 4]       │   [Task 2] 🛑   │   [Task 1]      │   [Feature A]   │
│  [Task 5]       │   [Task 3]      │                 │   [Feature B]   │
│                 │                 │                 │                 │
└─────────────────┴─────────────────┴─────────────────┴─────────────────┘
```

#### Главный принцип — WIP-лимиты (Work In Progress Limits):

На каждый столбец (кроме Backlog и Done) устанавливается **ограничение на количество одновременно находящихся в нем задач**.

> 💡 **Правило Kanban:** Нельзя брать новую задачу в статус `In Progress`, пока не завершена или не продвинута дальше одна из текущих. Это заставляет команду не _начинать_ новые задачи, а _заканчивать_ уже начатые.

#### Метрики Kanban:

- **Lead Time (Время выполнения):** Полный цикл — от момента создания задачи в бэклоге до статуса `Done`.
    
- **Cycle Time (Время цикла):** Время непосредственной работы над задачей — от `In Progress` до `Done`.
    

### 4. Сравнение: Scrum vs Kanban

|**Параметр**|**Scrum**|**Kanban**|
|---|---|---|
|**Философия**|Итеративная (ритм спринтов)|Непрерывный поток (Pull-система)|
|**Планирование**|Фиксировано на 1–2 недели (состав спринта заблокирован)|Динамическое (можно менять приоритеты бэклога в любой момент)|
|**Ограничения**|Ограничение по времени (Timebox спринта)|Ограничение по WIP-лимитам (количеству параллельных задач)|
|**Изменения**|Изменения внутри спринта не приветствуются|Изменения можно вносить в любой момент, пока задача в бэклоге|
|**Лучше всего подходит для**|Продуктовой разработки, запуска новых проектов и MVP|Поддержки (Support), DevOps, багфиксинга, персонального трекинга|

### 5. Scrumban: Гибридный подход

**Scrumban** объединяет лучшии черты обоих методов:

- Ритмичность планирования и ретроспективы берётся из **Scrum**.
    
- Наглядность доски, ограничение незавершенной работы (WIP) и гибкость в течение недели берутся из **Kanban**.
    

### 6. Полный стек фреймворков и инструментов

Все элементы твоей методологической системы от целей верхнего уровня до операционной реализации:

Plaintext

```
[ ИСПОЛНЕНИЕ И МЕТОДОЛОГИЯ (AGILE) ]
  ├── Scrum                      ──► Итерации (спринты), роли, события (Review/Retro)
  └── Kanban / Scrumban          ──► Непрерывный поток, WIP-лимиты, Lead/Cycle Time

[ УПРАВЛЕНИЕ, ЦЕЛИ И КОМАНДА ]
  ├── OKRs & SMART               ──► Амбициозные цели (OKR) и точные задачи (SMART)
  ├── RACI / RASCI Matrix        ──► Распределение ролей и ответственности (A, R, C, I)
  ├── Матрица Эйзенхауэра        ──► Важно / Срочно (Личный фокус на Q2)
  └── MoSCoW / RICE / Kano       ──► Приоритезация бэклога задач и фич

[ БИЗНЕС-АНАЛИЗ И АУДИТ ]
  ├── Lean Canvas / VPC / JTBD   ──► Продукт, ценность, клиенты
  └── SIPOC / 5 Why              ──► Аудит процессов и поиск корневых причин

[ КОРПОРАТИВНАЯ И СОФТВЕРНАЯ АРХИТЕКТУРА ]
  ├── TOGAF & ArchiMate          ──► Бизнес 🟡 + Софт 🔵 + Инфраструктура 🟢
  ├── BPMN / CMMN / DMN          ──► Исполняемые процессы, кейсы, правила решений
  ├── Process Flow (Flowchart)   ──► Пошаговые алгоритмы
  └── UML                        ──► Диаграммы Sequence, Class, Use Case

[ ДАННЫЕ И ИНТЕГРАЦИИ ]
  ├── DFD                        ──► Потоки данных
  ├── ERD                        ──► Схемы баз данных (PostgreSQL / Supabase)
  ├── ETL Framework              ──► Конвейеры обработки данных
  └── CRUD                       ──► Операции базы данных и REST API

[ ОРГАНИЗАЦИЯ И ТРЕКИНГ ]
  ├── Jira                       ──► Иерархия (Epics / Tasks / Sub-tasks)
  └── Obsidian                   ──► MOC / ACCESS / PARA
```

### 💡 Как использовать в вашей базе знаний:

В папке `03_Resources / Управление проектами` создай документ `Scrum_and_Kanban.md`.

- Для **личных проектов и обучения в Jira** идеально подходит доска типа **Kanban** с WIP-лимитом `In Progress = 2` или `3`, чтобы не распылять фокус.
    
- Для **командных разработок** выстраивай **Scrum** со спринтами по 2 недели.
