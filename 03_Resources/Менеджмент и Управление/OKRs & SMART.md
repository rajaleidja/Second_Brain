[[_MOC frameworks]]

### 1. Что это такое?

Если **Матрица Эйзенхауэра** помогает сортировать ежедневную рутину, а **RICE / MoSCoW** — расставлять приоритеты задачам в бэклоге Jira, то **SMART** и **OKRs** — это инструментарий **целеполагания**.

Они переводят абстрактные мечты («хочу стать крутым специалистом» или «надо поднять качество кода») в четкие, измеримые ориентиры на уровне отдельного человека, команды или всей компании.

### 2. SMART-цели: Стандарт формулировки понятных задач

Фреймворк **SMART** используется для постановки тактических целей и конкретных задач. Чтобы цель считалась качественной, она должна соответствовать 5 критериям:

Plaintext

```
┌─────────────────────────────────────────────────────────────────┐
│ S - Specific (Конкретная)    │ Четко определенный результат     │
│ M - Measurable (Измеримая)   │ Метрика успеха (в чем мерим?)    │
│ A - Achievable (Достижимая)  │ Реалистичность при имеющихся ресурсах│
│ R - Relevant (Релевантная)   │ Зачем это нужно? Связь с главными целями│
│ T - Time-bound (Огранич. во времени) │ Точный дедлайн           │
└─────────────────────────────────────────────────────────────────┘
```

#### Плохой пример vs SMART:

- ❌ **Плохо:** _«Сделать нормальную схему базы данных»_.
    
- ✅ **SMART:** _«К 15 сентября спроектировать ERD-схему PostgreSQL в Obsidian для 4 ключевых таблиц (Users, Courses, Enrollments, Feedbacks) с нормализацией до 3NF и настройкой FK-связей»_.
    

### 3. OKRs (Objectives and Key Results): Система амбициозного управления

Фреймворк, популяризированный Intel и Google, который связывает стратегическое видение с конкретными метриками. Состоит из двух частей:

1. **Objective (Цель):** Качественное, вдохновляющее и амбициозное направление (_Куда мы идем?_).
    
2. **Key Results (Ключевые результаты):** 3–5 строго измеримых метрик (_Как мы поймем, что пришли?_).
    

Plaintext

```
                     ┌─────────────────────────────────────────┐
                     │          OBJECTIVE (Цель)               │
                     │  "Построить масштабируемый сервис       │
                     │   ИИ-анализа отзывов на n8n и Postgres" │
                     └────────────────────┬────────────────────┘
                                          │
            ┌─────────────────────────────┼─────────────────────────────┐
            ▼                             ▼                             ▼
┌───────────────────────┐     ┌───────────────────────┐     ┌───────────────────────┐
│ Key Result 1 (KR1)    │     │ Key Result 2 (KR2)    │     │ Key Result 3 (KR3)    │
│ Время ответа API      │     │ Охват автотестами     │     │ Средняя точность      │
│ снижено до < 800 мс   │     │ покрывает 90%+ нод    │     │ классификации Gemini  │
│                       │     │ n8n                   │     │ достигает >= 95%      │
└───────────────────────┘     └───────────────────────┘     └───────────────────────┘
```

#### Главное отличие OKR от обычных KPI:

- **Амбициозность (Stretch Goals):** Достижение OKR на **70–80%** считается отличным результатом. Если OKR выполнен на 100% — цель была слишком простой.
    
- **Прозрачность:** Цели не привязываются к финансовым бонусам напрямую, что позволяет ставить рискованные, но прорывные ориентиры.
    

### 4. В чем разница между SMART и OKR?

|**Параметр**|**SMART**|**OKR**|
|---|---|---|
|**Уровень**|Тактический (задачи, личные цели, проекты)|Стратегический (направление квартала / года)|
|**Стиль**|Реалистичный (нужно выполнить на 100%)|Вызывающий / Амбициозный (70–80% = успех)|
|**Фокус**|Четкая отработка конкретного результата|Движение к большим изменениям через ключевые вехи|
|**Использование**|Формулировка и описание задачи в Jira / Obsidian|Планирование целей на год или квартал|

### 5. Полная система инструментов системного инженера (Complete Stack)

Теперь твоя матрица управленческих, архитектурных и инженерных методов стала абсолютна полна и замкнута на всех уровнях:

Plaintext

```
[ СТРАТЕГИЯ, ЦЕЛИ И ПРИОРИТЕТЫ ]
  ├── OKRs & SMART               ──► Постановка амбициозных целей (OKR) и четких задач (SMART)
  ├── Матрица Эйзенхауэра        ──► Важно / Срочно (Фокус на Q2-зоне)
  └── MoSCoW / RICE / Kano       ──► Приоритезация бэклога фич и задач

[ БИЗНЕС-АНАЛИЗ И АУДИТ ]
  ├── Lean Canvas / VPC / JTBD   ──► Продукт, ценность, клиенты
  └── SIPOC / 5 Why              ──► Верхнеуровневый аудит процессов и поиска проблем

[ КОРПОРАТИВНАЯ И СОФТВЕРНАЯ АРХИТЕКТУРА ]
  ├── TOGAF & ArchiMate          ──► Макро-уровень: Бизнес 🟡 + Софт 🔵 + Железо 🟢
  ├── BPMN / CMMN / DMN          ──► Процессы, кейсы, правила решений
  ├── Process Flow (Flowchart)   ──► Алгоритмы и блок-схемы
  └── UML                        ──► Диаграммы Sequence, Class, Use Cases

[ ДАННЫЕ И ИНТЕГРАЦИИ ]
  ├── DFD                        ──► Потоки данных
  ├── ERD                        ──► Проектирование схемы БД (SQL/Supabase)
  ├── ETL Framework              ──► Конвейеры (Extract ➔ Transform ➔ Load)
  └── CRUD                       ──► Операции с данными и API-методы

[ ОРГАНИЗАЦИЯ И ТРЕКИНГ ]
  ├── Jira                       ──► Иерархия (Epics / Tasks / Sub-tasks)
  └── Obsidian                   ──► MOC / ACCESS / PARA
```

### 💡 Как использовать в вашей базе знаний:

В папке `03_Resources / Управление проектами` создай документ `OKRs_and_SMART_Goals.md`.

Используй **OKR** для формулирования квартальных целей обучения и запуска сервисов, а **SMART** — для прописывания формулировок в конкретных Epics и Tasks в Jira.
